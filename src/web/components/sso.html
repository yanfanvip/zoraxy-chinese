转发认证

转发认证（Forward Auth）提供方的配置。

转发认证会向支持该协议的认证服务器发起子请求，然后：

  • 认证服务器返回 200–299 时，放行请求到后端。
  • 否则返回认证服务器的响应。

支持此方式的认证服务器示例：

  • Authelia
  • Authentik
  • OAuth2 Proxy
认证服务器 Forward Auth 端点的完整地址或 URL。示例： http://127.0.0.1:9091/authz/forward-auth
高级选项
从认证服务器响应复制到后端请求的头（逗号分隔，不区分大小写）。未设置则不复制。
示例： Remote-User,Remote-Groups,Remote-Email,Remote-Name
从认证服务器响应复制到返回客户端的响应的头（逗号分隔）。未设置则不复制。
示例： Set-Cookie,WWW-Authenticate
从原始请求复制到发往认证服务器的请求的头（逗号分隔）。未设置则复制全部。建议留空或使用下方示例。
示例： Accept,X-Requested-With,Cookie,Authorization,Proxy-Authorization
从原始请求复制到发往认证服务器的 Cookie 名称（逗号分隔，区分大小写）。未设置则包含全部。
示例： authelia_session,another_session
从发往后端应用的请求中排除的 Cookie 名称（逗号分隔）。用于排除仅给认证服务器使用的 Cookie。
示例： authelia_session,another_session

Zoraxy Auth

Zoraxy Auth 为内置 SSO 认证系统，可在 Zoraxy 内直接管理用户。

配置说明

使用 Zoraxy Auth 前请按以下步骤配置网关。

  1. 在下方开启 Zoraxy Auth 网关。
  2. 添加 HTTP 代理规则，将 SSO 域名转发到 Zoraxy Auth SSO 端口。
    例如 auth.example.com → localhost:5489
  3. 在下方将 SSO 重定向 URL 配置为 SSO 域名。
    例如 https://auth.example.com

退出登录说明

若站点使用 Zoraxy Auth 做 SSO，建议在应用导航或用户菜单中加入退出链接。

  1. 访问 SSO 域名并在 URL 后加 /logout。
    例如 https://auth.example.com/logout
  2. 点击「从所有服务退出」可结束所有已连接服务的会话。
